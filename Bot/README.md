# Article submission bot

The Python environment is defined in `pyproject.toml` and locked in `uv.lock`. Use `uv` to create and run it. The bot registers the Discord slash command `/submission`. Authorized users can submit one article at a time; the metadata and attached files are committed to `Front/content/<id>/` on the configured GitHub branch.

Each submission creates this layout:

```text
Front/content/<id>/
├── article.json
├── icon.png
└── article.pdf              # for PDF articles only
```

`article.json` uses the supplied `Article` shape. Its `icon` and file-based `content.path` values are paths relative to `Front/`, such as `content/<id>/icon.png` and `content/<id>/article.pdf`. External articles store an HTTPS URL in `content.url` and do not include a body file.

## Configuration

Set these environment variables before starting the bot:

| Variable | Required | Description |
| --- | --- | --- |
| `DISCORD_TOKEN` | Yes | Discord bot token |
| `DISCORD_ALLOWED_USER_IDS` | One of these two is required | Comma-separated Discord user IDs allowed to submit |
| `DISCORD_ALLOWED_ROLE_IDS` | One of these two is required | Comma-separated Discord role IDs allowed to submit |
| `GITHUB_TOKEN` | Yes | Fine-grained token for the target repository |
| `GITHUB_OWNER` | Yes | GitHub account or organization that owns the repository |
| `GITHUB_REPO` | Yes | Repository name |
| `GITHUB_BRANCH` | No | Existing target branch; defaults to `main` |

Grant the GitHub token **Contents: read and write** access to the target repository. The bot uses the Git database REST endpoints to add the article assets and metadata in one commit. It does not force-update the branch.

## Run

From the repository root, sync the bot environment and start it:

```sh
uv sync --project Bot
uv run --project Bot python Bot/main.py
```

The bot syncs its global application command when it starts. Discord may take a short time to show a newly registered global command.

## Submission rules

- The bot generates `id` as a UUID v4 (32 hexadecimal characters); users do not enter it. Each submission gets a new ID, even when its content is identical to an earlier submission.
- `date` must be a real date in `YYYY-MM-DD` format.
- `icon` must be a PNG (`.png`), up to 2 MiB and 16 million pixels. The PNG file signature is checked.
- `abstract` is plain text. Line breaks are preserved; markup is displayed as text.
- `content_type` must be `pdf` or `external`.
- External article URLs must use HTTPS.
- PDF body files must have the `.pdf` extension and be at most 20 MiB. PDFs are checked for their file signature.

## Tests

Run the submission and schema tests without connecting to Discord or GitHub:

```sh
uv run --project Bot python -m unittest discover -s Bot
```

## Implementation

- `main.py`: Discord command, authorization, and attachment checks (extension, size, and file contents).
- `models.py`: Pydantic models for the article schema and environment settings. Repository paths are generated by the bot from the validated article ID.
- `github.py`: one `upload_article` function using `httpx.AsyncClient`, scoped to each submission.

## Formatting

Run Black from the repository root:

```sh
uv run --project Bot black Bot
```

Check formatting without changing files:

```sh
uv run --project Bot black --check Bot
```
